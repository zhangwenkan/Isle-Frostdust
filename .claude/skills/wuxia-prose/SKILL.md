# 孤屿霜尘 · 武侠文案转化

把用户以后陆续扔来的**口头剧情、人设、半截对话**，变成能进游戏的：

1. 整理过的剧情骨架（不丢用户原意）
2. 可演出的对白（古龙）
3. 场景旁白 / 过场（金庸叙事 + 梁羽生意境）
4. 名物、门派、招式、文书（温瑞安气势或真正文言）

本 skill **蒸馏的是笔法，不是原著正文**。禁止整段复述、摘抄金庸古龙等作品，禁止挪用原著人名、门派、招式、器物。

每次转化前先读：

- [references/blend.md](references/blend.md) — 五家怎么分工
- [references/voice.md](references/voice.md) — 对白铁律（古龙）
- [references/register.md](references/register.md) — 对白 / 旁白 / 文书 语域
- [references/plot.md](references/plot.md) — 剧情整理与规划
- [references/game-format.md](references/game-format.md) — 产出格式
- [references/anti-patterns.md](references/anti-patterns.md) — 禁止项

已有剧情与人设在 `narrative/bible/`。用户新丢的口头稿进 `narrative/inbox/`，转化结果进 `narrative/scenes/`。

## 何时动手

用户出现这些意图就走本流程，不必等他们说「用 skill」：

- 丢一段口语剧情、人设、对话
- 「转化 / 润色 / 写成武侠文 / 古龙风 / 文言文一点」
- 「帮我整理这章 / 规划后面」
- 给某个岛、某人、某场对话写文案

用户**还没给具体剧情**时：不要虚构主线。只说明工具已就绪，等他们下一段口头稿。可用无名屿做**示范**，示范须标明不是正史。

## 五步流程（每次都走）

### 1. 收口头稿，不先写美文

从用户这段话里拆出四堆，缺的标「未给」：

| 堆 | 问的是 |
| --- | --- |
| 事实 | 谁在哪、发生什么、玩家能做什么 |
| 人 | 在场角色、性格、彼此关系、隐瞒了什么 |
| 口吻 | 用户已有的原话、想要的情绪 |
| 玩法 | 战斗、探索、选项、是否可失败 |

口头稿含糊时，**先整理骨架再提问**，不要一上来写成篇。一次最多问 3 个关键缺口（身份、隐瞒、这场要让玩家感到什么）。

### 2. 先规划，后润色

按 [references/plot.md](references/plot.md) 把这场放进更大结构：

- 这场在弧里的位置（起、承、折、泄、钩）
- 玩家**此刻**知道什么、角色**另外**知道什么
- 结束时必须留下的钩子（一物、一口误、一个不答）
- 与 `narrative/bible/` 已有设定是否打架

若只是单句对白润色，骨架可极短，但不能不想「这句话在隐瞒什么」。

### 3. 分语域写

不要整场都「古文」。按 [references/register.md](references/register.md)：

| 语域 | 默认笔法 |
| --- | --- |
| 人物开口 | **古龙**短句白话，冷、跳、留白 |
| 场景旁白、过场 | 金庸叙事清楚 + 梁羽生一点意境 |
| 招式 / 门派 / 刀剑名 | 温瑞安对仗或金庸意象，原创 |
| 密信、碑、判词、祭文 | 真正文言，短 |
| 茶馆传闻、说书 | 卧龙生的快与钩 |

用户若当场指定「这一句要更文言 / 更闹 / 更悲」，以当场为准，改完在场景头注记。

**古龙 ≠ 之乎者也。** 用户说「偏文言文」时，优先把文言气放在旁白和文书；对白仍是古龙白话，只是比现代口语更干净、更少解释。满口「汝等何人」「岂非」是失败。

### 4. 按游戏格式交稿

输出两块，都给用户看：

**A. 整理** — 骨架、人物立场、信息差、钩子、待确认  
**B. 正文** — 按 [references/game-format.md](references/game-format.md) 的场景稿（旁白、对白、指令、选项）

对白要短，适合字幕：一句一行，单行一般不超过 18 字，最长不超过 24 字。需要「一段话」就拆成连续气泡。

### 5. 落盘（有实质剧情时）

用户这段是正式剧情而非闲聊示范：

1. 口头稿写入 `narrative/inbox/YYYYMMDD-<短标题>.md`
2. 转化稿写入 `narrative/scenes/<场景id>.md`
3. 新稳定人设 / 世界设定，**问一句**是否写入 `narrative/bible/`，得到同意再改圣经

用户说「先看看」就只在对话里交稿，不落盘。

## 转化时的判断顺序

1. 有没有把用户原意说拧了？（最优先）
2. 对白像不像古龙的**冷**，而不是相声？
3. 旁白清不清楚——玩家能否知道自己在哪、该干什么？
4. 有没有抄到原著人名招式？
5. 这场结束有没有钩子？

## 示范与正史

`narrative/_example/` 是工具示范，**不是**游戏剧情。用户尚未口述的主线，不得写进 `narrative/bible/`。
